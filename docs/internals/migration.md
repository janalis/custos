# Custos — Go port of Php Inspections (EA Extended)

## Context

The repository starts empty. Goal: a fast, standalone PHP inspector + fixer ("custos") that ports **all 178 inspections and ~140 quick-fixes** of Php Inspections EA Extended (`~/Sites/phpinspectionsea`, Java/IntelliJ, v6.4.0), usable from CI and from editors.

Decisions taken with the user:

- **Go**, with a **hand-written PHP 8.5 parser** (no cgo, single static binary) and own type engine.
- **Editor integration = LSP server** (`custos lsp`), run as a supplementary PHP server next to the editor's main one.

Key facts from exploration:

- EA: 178 inspections registered in `src/main/resources/META-INF/plugin.xml` (shortName, group, level, enabledByDefault); ~110 are syntax-only, ~68 need type inference / reference resolution / class hierarchy (`utils/OpenapiResolveUtil`, `PossibleValuesDiscoveryUtil`, `InterfacesExtractUtil`, `OpenapiControlFlowUtil`, PhpStorm stubs).
- 66 fixes are `UseSuggestedReplacementFixer` (replace node with text) → a generic text-edit fixer covers most.
- 40 inspections have options (public UPPER_CASE fields); 42 gate on PHP language level (`openApi/PhpLanguageLevel`); global `ComparisonStyle` (regular/yoda).
- Conformance gold: `testData/fixtures/` (436 php, 134 `.fixed.php`, `<warning|weak_warning|error descr="[EA] …">` markup) driven by 182 Java test classes that set inspection, options and PHP level → extractable into a manifest.
- 177 description HTMLs in `src/main/resources/inspectionDescriptions/`; messages hard-coded in Java with `[EA] ` prefix.
- **License: EA is LGPL-2.1; custos will be MIT** → **clean-room reimplementation** (user decision). See "Clean-room process" below.

## Clean-room process (MIT)

- **Never** copy or translate EA Java code, messages, descriptions, docs or fixtures into the custos repo.
- Facts are fine to reuse: rule identifiers (shortNames, kept for `@noinspection` compatibility), groups, default severity/enabled flags, option names, PHP-version thresholds.
- Two-step per rule, done by different agents/sessions:
  1. **Spec** (`specs/<RuleID>.md`, written in our own words): what is detected, exceptions, options, PHP-version gating, what the fix produces, plus *new* minimal PHP examples. The spec author may read EA; the spec must not contain EA code or verbatim text.
  2. **Implement** from the spec only (implementer does not open EA Java sources). Messages, descriptions (`custos explain`) and unit-test fixtures are written fresh.
- **Conformance against EA without redistribution**: `make conformance` reads fixtures directly from a local EA checkout (`EA_PATH`, default `~/Sites/phpinspectionsea`) at test time; the case manifest generated by `tools/extract` lives outside git (`.cache/ea-cases.json`) or holds only facts (fixture path, rule ID, options, PHP level). Comparison = rule + range + severity, and the result of applying fixes vs `.fixed.php` (whitespace-normalised); message text is not compared. Skipped in CI when EA isn't present; custos' own fixtures are the CI gate.
- Third-party data: jetbrains/phpstorm-stubs (Apache-2.0, compatible) generated into the embedded index with attribution in `NOTICE`.

## Architecture (Go module `custos`, Go 1.27)

```text
cmd/custos/            main: analyse | fix | lsp | rules | explain | version
internal/syntax/       token, lexer, parser, ast, visitor, printer (lossless)
internal/phpdoc/       PHPDoc tag + type-expression parser
internal/names/        namespace/use resolution, FQN of every name
internal/index/        project symbol index (classes, members, functions, consts), on-disk cache
internal/stubs/        phpstorm-stubs compiled to a binary index, go:embed
internal/types/        Type model (interned unions), expression inference, builtin return overrides
internal/flow/         local CFG, possible-values discovery, variable usage
internal/analysis/     Rule interface, registry, dispatcher, Context, suppressions
internal/analysis/util/ ports of OpenapiTypesUtil, ExpressionSemanticUtil, OpenapiEquivalenceUtil, PhpLanguageUtil…
internal/fix/          TextEdit, conflict resolution, apply-until-fixpoint
internal/rules/<group>/ one file per inspection + _test.go (groups mirror EA groupName)
internal/config/       custos.json loader, PHP version from composer.json, per-rule options
internal/report/       text, json, checkstyle, sarif, github annotations
internal/lsp/          JSON-RPC 2.0 stdio server (own minimal impl, no heavy deps)
internal/conformance/  fixture markup parser + runner against extracted manifest
tools/extract/         reads an EA checkout → rule facts (meta.json) + local-only conformance case list
specs/                 one clean-room behavioural spec per rule (our own words)
testdata/rules/<ID>/   custos' own fixtures (*.php with expectation markup, *.fixed.php)
docs/                  migration.md, rules.md (generated status table), architecture.md
```

### Parser (performance-critical)

- Hand-written lexer (state machine incl. heredoc/nowdoc, string interpolation, `?>` inline HTML, casts, attributes) producing a flat `[]Token` with byte offsets (`uint32`) and trivia (whitespace/comments) kept → lossless, fixes edit exact byte ranges.
- Recursive-descent + Pratt expression parser, PHP 8.5 syntax (property hooks, asymmetric visibility, pipe operator `|>`, enums, readonly, first-class callables, attributes, match, named args). Error-tolerant: recovery at statement/member boundaries, `Bad*` nodes, so the LSP works on broken code.
- **Version-aware, PHP 5.3 → 8.5**: parser takes a target `PhpVersion`; keywords introduced later (`fn`, `match`, `enum`, `readonly`, `never`…) are plain identifiers below their version, newer syntax (arrow fns, nullsafe, named args, attributes, hooks, pipe…) parses but emits a `syntax/unsupported-in-version` diagnostic. Legacy syntax still accepted (`<%` / `<?` short tags when configured, `${var}` interpolation, curly offsets `$a{0}`, `(real)`/`(unset)` casts) so EA's Language-level-migration rules can flag it. Lexer keyword tables keyed by version; corpus tests run per version.
- AST nodes allocated in a per-file arena (slices of concrete structs, `NodeID uint32` references) → few allocations, cache-friendly, cheap to drop. Parent links stored in a side array.
- Validation: `go test -fuzz` (no panics, round-trip `print(parse(src)) == src`); corpus test parsing a real-world vendor tree + a pinned php-src test set, cross-checked against `php -l` (zero false syntax errors).

### Analysis engine

- `Rule` interface: `Meta()` (ID = EA shortName minus `Inspection`, group, default severity, enabledByDefault, min PHP version, options schema, description) + `Kinds()` (node kinds subscribed) + `Check(ctx, node)`.
- **Single tree walk per file**: dispatcher builds a kind→rules table once; each node visited once and handed to subscribed rules only.
- Semantic data is **lazy**: `ctx.TypeOf(expr)`, `ctx.Resolve(ref)`, `ctx.Class(fqn)` compute and memoize per file; syntax-only runs never touch the index.
- Files analysed in parallel (worker pool = GOMAXPROCS); index built in a first parallel pass and cached on disk (`.custos/cache`, keyed by path+mtime+size+content hash, versioned by binary build ID).
- Report: `ctx.Report(node|range, msg, fixes...)`; fix = list of `TextEdit` (+ title). Messages written fresh (clean-room).
- Suppression: honour PhpStorm `/** @noinspection XxxInspection */` and `// @noinspection` (EA users already have these), plus `@custos-ignore <id>`; baseline file support.
- Severity map: ERROR→error, WARNING→warning, WEAK WARNING→info (LSP Information).

### Fixer

- Collect edits per file, sort, drop overlapping ones (first rule wins), apply, re-parse and re-run until no fixes or 10 iterations. `custos fix --rule=… --dry-run --diff`.

### Semantic layer (needed for ~68 rules)

- Names → index (project + vendor + embedded phpstorm-stubs, Apache-2.0, generated by `go generate` using custos' own parser).
- Types: `Type` = interned union of atoms (scalars, class FQN, array shapes kept simple, generics only as far as PHPDoc `array<K,V>`/`list<T>`), inference from literals, declared types, PHPDoc, assignments in scope, return types, builtin signatures; plus hand-written return-type overrides for builtins whose stub types are too loose (`str_replace`, `preg_replace`, `explode`, `current`…), derived from PHP's documented behaviour.
- Hierarchy: superclass/interfaces/traits walk, member lookup with inheritance (port `InterfacesExtractUtil`, `resolveMethod/resolveField`).
- Flow: per-function CFG sufficient for `OpenapiControlFlowUtil`/`OpenapiElementsUtil` users and `PossibleValuesDiscoveryUtil`.
- Target fidelity = EA fixtures pass, not PHPStan-level soundness.

### Config (`custos.json`, project root)

`{ "php": "8.3", "comparisonStyle": "regular|yoda", "paths": [...], "exclude": [...], "rules": { "OneTimeUseVariables": { "enabled": true, "severity": "warning", "options": { "ALLOW_LONG_STATEMENTS": false } } } }`. PHP version (any 5.3–8.5) defaults to composer.json `require.php` lower bound (or `config.platform.php`), else 8.4; drives both parser mode and rule gating (`Meta().MinPHP/MaxPHP`, port of EA's 42 `PhpLanguageLevel` checks). Stubs filtered by version via phpstorm-stubs `@since`/`@removed` tags. Same struct accepted as LSP `initializationOptions`.

### LSP server (`custos lsp`)

- Capabilities: full/incremental `textDocumentSync` (incremental), `codeActionProvider` with kinds `quickfix`, `source.fixAll.custos`, `resolveProvider: true`; `executeCommandProvider` (`custos.fixFile`, `custos.fixRule`).
- Push `publishDiagnostics` with real ranges, `code` = rule ID, `codeDescription` link, `source: "custos"`, `tags` (unnecessary for unused/dead-code rules). Debounced (~150 ms) re-analysis on didChange, from the in-memory buffer; index updated incrementally for the changed file only.
- Code actions matched by **code + range** (some clients drop `data`); action carries its own `data` (uri, version, rule, offset) and the edit is computed in `codeAction/resolve`.
- Workspace index built in background on `initialized`; syntax-only diagnostics available immediately.

## Migration plan (phases)

### Phase 0 — Bootstrap

- `git init`, `go mod init custos`, LICENSE (MIT), NOTICE (phpstorm-stubs attribution; "inspired by Php Inspections EA, independent clean-room implementation"), `.gitignore`, `Makefile` (`build`, `test`, `lint` via golangci-lint, `fuzz`, `bench`, `conformance`, `verify` = all gates), GitHub Actions workflow.
- `CLAUDE.md`: purpose, layout, commands, conventions (rule file template, no rule without own fixtures, perf budget) and the **clean-room rules** (never copy/translate EA code or text; implementers work from `specs/` only).
- `.claude/settings.json` allowing `go`/`make` commands; two skills making the 178 rules mechanical and parallelizable:
  - `.claude/skills/spec-rule/SKILL.md`: study EA inspection + tests → write `specs/<ID>.md` in own words with new examples; checklist forbids verbatim text/code.
  - `.claude/skills/implement-rule/SKILL.md`: from `specs/<ID>.md` only → Go rule + own fixtures + fix test → `make conformance RULE=<ID>` → update `docs/internals/rules.md`.
- `docs/internals/migration.md` (this plan) and `docs/internals/rules.md` status table.

### Phase 1 — Extraction & conformance harness

- `tools/extract`: parse `plugin.xml` (real XML parser — one displayName contains `>`), `RULES.md`, and the Java tests (regex over `configureByFile`, `setLanguageLevel`/`PhpLanguageLevel.set`, option field assignments, `checkResultByFile`) → `internal/rules/meta.json` (facts only: ID, group, level, enabledByDefault, option names/defaults, has-fix) + local-only `.cache/ea-cases.json` (fixture path in EA checkout, rule, options, PHP level, fixed file). Hand-patch the few tests regex can't read.
- `internal/conformance`: one markup parser for both EA fixtures (`<warning descr=…>`) and custos fixtures; run rule; compare rule/range/severity; apply all fixes and diff against `.fixed.php`. `make conformance` (EA, local) and `make fixtures` (own, CI) print pass/fail per rule and update `docs/internals/rules.md`.
- Write specs for the first batch of rules (Phase 5 runs spec → implement as a pipeline).

**Phase 2 — Syntax layer**: lexer, parser, AST, visitor, printer, fuzz + corpus tests, benchmarks (`BenchmarkParse` on large vendor files). Exit: zero false syntax errors on corpus, round-trip exact.

**Phase 3 — Engine, fixer, CLI, reporters**: dispatcher, Context, suppressions, config, fix loop, `analyse`/`fix`/`rules`/`explain`, reporters. Write our own analysis helpers covering the same needs as EA's utils (node-kind predicates, paren unwrapping, condition flattening, enclosing scope, structural equivalence, literal checks, test-context detection, "resolves to global builtin function" via names + builtin list). First end-to-end rule: `UnnecessarySemicolon`.

**Phase 4 — LSP** (can run in parallel with Phase 5): `internal/lsp`.

**Phase 5 — Wave A: ~110 syntax-only rules**, group by group (Code style, Control flow, Language level migration, Performance, Confusing constructs, Unused, Security, PHPUnit-syntactic…). Each rule = spec → Go file + own fixtures + fix test + EA conformance green. Parallelizable with the `spec-rule` / `implement-rule` skills (separate agents per step).

**Phase 6 — Semantic layer**: phpdoc, names, stubs generator, index + cache, types, hierarchy, flow.

**Phase 7 — Wave B: ~68 semantic rules** (heaviest last: NullPointerException, OffsetOperations, TypeUnsafeComparison, ProperNullCoalescingOperatorUsage, CallableParameterUseCaseInTypeContext, PHPUnit mocking, SenselessProxyMethod, ClassOverridesFieldOfSuperClass). `SecurityAdvisories` reads composer.json/lock (fixtures include 15 json files).

**Phase 8 — Hardening & release**: perf pass with pprof, real-project smoke runs (Symfony, Laravel, private projects) checking for crashes and false-positive rate, goreleaser builds (darwin/linux/windows, amd64/arm64), editor setup docs.

## Performance budget (enforced by `make bench`)

- Parse ≥ 50 MB/s single core; full syntax-only analysis of a large `vendor/` tree (~thousands of files) in < 1 s on M-series with all cores.
- Warm-cache full semantic run on a large project < 3 s; LSP re-analysis of one edited file < 30 ms p95.
- Memory: AST arenas freed per file in CLI mode; only the index stays resident.

## Verification

- `make verify`: gofmt/golangci-lint, `go test ./...` (unit + rule tests), `make fixtures` (own fixtures, CI gate), `make conformance` (local EA fixtures: rule/range/severity and `.fixed.php` match), fuzz smoke (30 s), benchmarks vs budget.
- CLI: `custos analyse src --format=json`, `custos fix --dry-run --diff` on a copy of a real project; re-run analyse to confirm fixes leave no re-reported issues and `php -l` passes on every fixed file.
- LSP: integration tests driving `custos lsp` over stdio (initialize → didOpen → diagnostics → codeAction → resolve → apply). In an editor: open a PHP file with a flagged construct, see the diagnostic, apply the offered fix.
- Progress tracking: `docs/internals/rules.md` shows 178/178 rules ported with conformance status.

## PHP engine support wave (2026-10-09)

- Parser: reject mixed first-class callable placeholders and invalid foreach
  targets while preserving recovery and the boundary between grammar errors
  and compile-time restrictions.
- Index: typed trait constants retain their importing class through nested
  traits and inheritance; relative types bind against that owner. Lookup is
  bounded, cycle-safe, and conservative for conflicting trait declarations.
- Inference: array filtering resolves named arguments and nullable callbacks;
  array mapping preserves single-input keys and models bounded null-callback
  zips with padding. Unknown inputs retain conservative array types.
- Work split: parser, constant indexing, and array inference have independent
  owners; the coordinator integrates constant typing and downstream fixtures.
  Anonymous classes, full DNF types, and broader method callbacks remain
  separate follow-up work.

## PHP correctness follow-up (2026-10-09)

- Three parallel owners cover operand/declaration grammar, quoted PHPDoc
  scanning, and cross-file declaration builtin resolution. The coordinator
  owns inference regressions and repository verification.
- Empty unset/isset lists and invalid unset operands produce syntax errors.
  Declaration clauses respect class, interface, trait and enum grammar;
  recovery retains clause names, declaration bodies and following statements.
  Compile-time restrictions remain separate from parser validation.
- PHPDoc scanning preserves whitespace and escaped bytes inside quoted keys
  and literals. Quoted delimiters do not affect nesting or type splitting;
  unfinished literals cannot claim complete type metadata.
- Namespace-fallback define/class_alias candidates retain their provenance.
  Index lookups check the complete project, including layered indexes and
  incremental additions/removals, before using those declarations. Index-time
  body inference excludes provisional declarations because other project
  files may shadow their calls; ordinary analysis uses the complete index.
- Anonymous-class identities, generic array key metadata and broader
  PHPStan/Psalm annotation selection remain separate follow-up work.
